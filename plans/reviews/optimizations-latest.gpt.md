# Runtime performance review

This is a **static, read-only review** of the repository packed in `repomix-output.xml`. No timing or speedup was measured; no project binary, build, or test was run. Four read-only reviewers examined separate subsystems, and I checked their findings against the cited call paths and existing protections. Priorities reflect expected user impact, confidence in the cost mechanism, and change risk. No P0 issue was established.

## Findings

### P1 — Material interactive or sustained background cost

1. **Ligature invalidation grows quadratically on full text redraws.** In `libs/draxul-runtime-support/src/grid_rendering_pipeline.cpp:64–116`, each dirty cell expands through its entire same-highlight text run before the results are sorted and deduplicated; `:288–300` invokes this with ligatures enabled by default. A fully dirty 200×80 homogeneous grid emits 3.2 million temporary entries for 16,000 final cells, delaying the main-thread flush. Six-cell shaping and scratch reuse do not bound this expansion. **Change:** merge touched runs per row before emitting cells, preserving the documented split-run behavior. **Validate:** count comparisons, entries, retained scratch capacity, and flush time as row width doubles; require emitted work to scale with covered cells, with ligature, wide-cell, atlas-retry, Vulkan, and Metal regressions. **Dependency:** none.

2. **Rezonality recreates immutable GPU resources during viewport dragging.** Width or height changes make the active generation incompatible in `plugins/rezonality/src/native_backend_vulkan.cpp:2167–2188` and `src/native_backend_metal.mm:711–731`; render-time preparation then recreates models, textures, and pipelines. Metal also repeats shader conversion and library compilation. Each distinct drag size can stall the render path and temporarily retain retired generations. **Change:** keep source-generation assets separate from size-dependent targets, reusing compatible pipelines while preserving frame-slot retirement. **Validate:** record drag-frame p95, pipeline creations, upload bytes, and peak memory on an asset-rich scene; check reload failure, format changes, and Vulkan/Metal output. **Dependency:** independent of the watcher finding below.

3. **Rezonality hashes the whole project every watch poll.** `ProjectPipeline::fingerprint()` enumerates, sorts, reads, and hashes every regular file except `.git` (`plugins/rezonality/src/live_project.cpp:1238–1277`); the worker repeats this after 100 ms waits (`:1544–1555`), including for hidden panes. An unchanged asset-heavy tree therefore costs O(total file bytes) per scan. Background execution protects the UI thread, but not CPU, storage traffic, or power. **Change:** use directory notifications and a bounded per-file fingerprint index, with overflow rescans and same-size edit handling; retain arbitrary shader-include suffix coverage. **Validate:** compare idle bytes read and worker CPU, then edit/break/repair and nested-include behavior on Windows/macOS; target no full-content reads while unchanged. **Dependency:** none; the completed include-watching card addresses coverage, not polling cost.

4. **Paused SatView continues catalog-wide propagation.** Its worker retains a 16 ms deadline while paused (`plugins/satview/src/runtime/satview_simulation_worker.cpp:289–333`) and still calls `propagate_satellites()` and publishes a generation (`:368–380,444–476`) at an unchanged simulation time. Cached models and skipped future-position propagation reduce work but do not stop the first propagation. **Change:** publish the settled paused state, then wait for catalog, clock, setting, resume, or shutdown changes; reset the deadline on resume. **Validate:** count propagations and worker CPU for a fixed catalog; require zero calls after the settled pause and prompt output after an explicit change. Check worker shutdown and both platforms. **Dependency:** none; the completed pause-state card did not remove this worker loop.

### P2 — Credible bounded-workload improvements


6. **Kanban reload reads every board card on the GUI thread.** A debounced native invalidation calls `reload_board()` from `KanbanHost::pump()` (`modules/kanban/draxul-kanban/src/kanban_host.cpp:265–281,466–484`). Workspace loading visits every discovered board and opens each card for up to 40 priority lines (`src/kanban_store.cpp:255–262,655–660,714–727`). One edited card can thus cause N file opens and scans, even in a background tab. Notifications and the 150 ms debounce limit frequency, not main-thread I/O. **Change:** perform one full scan on an owned worker, coalesce subsequent invalidations, and publish a generation-checked snapshot. **Validate:** inject slow reads in a 5,000-card workspace while typing elsewhere; target no GUI-thread file reads and preserve moves, failures, previews, and shutdown on both platforms. **Dependency:** separate from finding 20’s metadata matching.

7. **Markdown scrolling copies and sorts the complete layout.** Every dirty draw-list rebuild calls `document_with_scrollbar()` (`modules/markdown/draxul-markdown/src/markdown_host.cpp:432–449,555–586`), which copies all rows, text, and decorations and sorts them to append two scrollbar decorations. Wheel and drag changes trigger this despite retained layout and visible-row culling later in the draw-list builder. **Change:** build from the retained layout and append the scrollbar drawing separately, preserving clipping and paint order without another document cache. **Validate:** compare allocations, copied rows, and scroll time at fixed viewport size for 1,000 and 100,000 rows; require zero full-document copies and correct mixed-height/table rendering on both backends. **Dependency:** none.

8. **Height-only ScoreView resizing reengraves every paged score page.** `ScoreRuntime::set_viewport()` marks layout dirty for any size change (`plugins/scoreview/product/draxul-scoreview/src/score_runtime.cpp:347–352`), although its engraving options use width, scale, and zoom (`:574–580`). The next pump invokes Verovio layout and renders/interprets each page (`:582–633`). Dirty coalescing does not prevent repeats across drag frames. **Change:** invalidate engraving only when its actual inputs change; clamp scroll and redraw for height changes. **Validate:** count `RedoLayout`, SVG renders, and frame p95 while dragging height on a long score; require zero reengraves after initial layout, with width/DPI/zoom and Windows/macOS snapshot checks. **Dependency:** none.

9. **Live remote-terminal publications receive a second full-grid copy on the GUI thread.** `RemoteTerminalHost::pump()` constructs `display_snapshot` by value even in the ordinary live branch (`libs/draxul-host/src/remote_terminal_host.cpp:1204–1208`), then applies only dirty cells (`:1296–1299`). The worker publication already owns a snapshot (`libs/draxul-client/src/remote_session_coordinator.cpp:943–945`). Sparse or metadata-only updates therefore copy and destroy every string-bearing cell on the GUI thread; visibility suppression and publication coalescing do not remove that copy. **Change:** reference the live publication and allocate a composed snapshot only for scrollback. **Validate:** count cell copies and pump time for sparse updates at 200×60 and larger sizes; require zero live-branch full copies and identical resize/scrollback output on both platforms. **Dependency:** none.

10. **Both grid backends rewrite unchanged cells on every draw.** Metal calls `RendererState::copy_to()` in `metal_renderer.mm:106–132`; Vulkan does likewise in `vk_renderer.cpp:203–224`. `renderer_state.cpp:62–77,360–368` also clears the unused tail of a 16,384-cell overlay region. A 200×80 pane writes about 3.63 MB per draw even if only another pane animates. Existing dirty-span and overlay flags are not used by these uploads. **Change:** track content generations per frame slot and upload only that slot’s missing dirty regions; initialize and clear overlay tails only as needed. A single global dirty flag would be unsafe with two slots. **Validate:** count copied, zeroed, and flushed bytes; require zero base-cell bytes on unchanged and cursor-only frames after slot priming, with resize and overlay-shrink checks on Vulkan/Metal. **Dependency:** both native backends and shared renderer state.

11. **Terminal resizing queues an unchanged full glyph atlas.** A cell-dimension change forces a redraw in `libs/draxul-host/src/terminal_host_base.cpp:293–316`; `grid_host_base.cpp:196–219` also forces an atlas upload. `grid_rendering_pipeline.cpp:328–343` sends the full 2048² RGBA atlas even when glyph pixels have not changed, and `pending_atlas_upload.h:36–49` copies 16 MiB before pending uploads can coalesce. **Change:** keep grid invalidation separate from atlas invalidation while preserving first upload and font/atlas resets. **Validate:** count queued, staged, and GPU atlas bytes during warmed-atlas pane dragging; target zero texture bytes when existing glyphs suffice and verify Vulkan/Metal text after resize. **Dependency:** independent of the completed atlas-reset correctness work.

12. **Neovim prepares multiple redraws before one possible presentation.** `NvimHost::pump()` drains all notifications (`libs/draxul-host/src/nvim_host.cpp:194–201`), and each `flush` immediately prepares grid cells and glyphs (`:464–475`; `libs/draxul-runtime-support/src/grid_rendering_pipeline.cpp:288–318`). App presents only after pumping (`app/app.cpp:2490–2494,2536–2539`). Under a queued macro or fast scroll, M complete redraws of the same area incur M preparations although only the last is shown. **Change:** apply semantic events in order but coalesce GPU preparation across already available complete redraw transactions; preserve first-flush startup and a trailing partial transaction. **Validate:** queue 1/10/100 complete redraws and require one final preparation with identical cells/cursor; cover partial tails, resize, atlas reset, and both backends. **Dependency:** complements finding 1.

13. **MegaCity camera motion rebuilds the world snapshot.** A camera change marks `scene_dirty_` (`plugins/megacity/product/draxul-megacity/src/megacity_host.cpp:1491–1505`), and the next pump republishes the complete scene (`:1559–1573`). `scene_snapshot_builder.cpp:245–338,464–493,536` revisits ECS objects, materials, meshes, strings, and ordering. Idle suppression and mesh-upload caching do not avoid this CPU work during pan/orbit. **Change:** distinguish camera-only changes from world/material changes; reuse object records while updating camera-dependent grid, depth, and transparent order. Avoid a second full object cache. **Validate:** replay camera motion over increasing scene sizes; require zero full ECS snapshot rebuilds after initial publication and preserve selection, labels, transparency, and Vulkan/Metal views. **Dependency:** separate from the pending backend frame-preparation card.

14. **MegaCity records offscreen objects in its main geometry passes.** The snapshot includes all renderables (`plugins/megacity/product/draxul-megacity/src/scene_snapshot_builder.cpp:327–338`), and Vulkan (`draxul-codeviz-renderer/src/codeviz_render_vk.cpp:3712–3718,3913–3925`) and Metal (`src/codeviz_render.mm:1700–1765`) issue per-object draws without camera-frustum rejection. Zooming into a small part of a large city leaves CPU command recording and vertex work proportional to total objects. Mesh caching and hardware clipping occur too late to remove those costs. **Change:** use conservative per-object bounds for camera-pass culling; leave shadow visibility independent. **Validate:** increase offscreen objects while holding visible content fixed; require camera-pass draws to follow the intersecting subset, with boundary, custom-mesh, shadow, and backend checks. **Dependency:** bounds shared by both product renderers.


16. **Monolithic ScoreView Flow replays offscreen notation every playback frame.** The presentation scissors pixels but passes the full strip to NanoVG (`plugins/scoreview/product/draxul-scoreview/src/score_presentation.cpp:327–333`); `src/score_render_nvg.cpp:157–180,264–269` walks paths and glyph outlines without viewport rejection. Active Flow schedules roughly 16 ms frames (`score_runtime.cpp:1746–1752`). Long Clock scores and monolithic fallbacks pay for distant notation; normal windowed Roll and paged views already bound their work. **Change:** store conservative interpreted-object bounds and skip offscreen submissions, invalidating bounds with engraving replacement. **Validate:** count submitted paths/glyphs and frame p95 on long Clock/fallback scores; require output at clip edges to match on Vulkan/Metal. **Dependency:** none.

17. **ScoreView saves complete progress synchronously at dirty bar transitions.** `ScoreRuntime::pump()` calls `flush_at_bar()` (`plugins/scoreview/product/draxul-scoreview/src/score_runtime.cpp:1703–1713`), which serializes the whole model and writes, flushes, closes, and renames a file (`src/score_session_controller.cpp:105–124`; `product/draxul-score-learn/src/progress_store.cpp:43–69`). Bar gating and a 200-session cap limit frequency and history, but long-piece state and storage latency still enter the playback thread. **Change:** use one coalescing worker fed immutable, versioned snapshots; bound queued versions and preserve final flush and failures. **Validate:** compare pump p95/p99 and written bytes on long progress with slow storage; require latest-state persistence and shutdown recovery on Windows/macOS. **Dependency:** none.

18. **Rezonality activation copies its CPU asset build.** `RuntimeController::activate_prepared()` copies `ShaderBuild` before replacing `active_build_` (`plugins/rezonality/src/runtime_controller.cpp:47–62`), including same-build resize recovery; the build owns shader, model, and pixel vectors. The copy occurs in frame preparation and temporarily duplicates O(asset bytes), even if GPU resize reuse is later fixed. **Change:** move a pending build into active storage; for active-build recreation, retain it and update status without self-copying. **Validate:** count copied bytes, allocations, and peak memory for asset-heavy reload/resize; preserve failed-preparation and Vulkan/Metal generation behavior. **Dependency:** independent of finding 2.

19. **Vulkan retains Rezonality’s one-time texture staging buffers.** Static image/model textures allocate persistent mapped upload buffers (`plugins/rezonality/src/native_backend_vulkan.cpp:540–559,621–639`). After the one-time image initialization (`:1875–1881,1934–1941`), those buffers remain until the whole generation is destroyed; completion retirement handles old generations only (`:2206–2223`). A 4096² RGBA8 texture can leave 64 MiB of staging storage resident. Per-frame audio buffers must remain. **Change:** retire initial upload buffers with their submitting frame slot after completion, including aborted-submit handling. **Validate:** measure staging allocation after initial frames and reloads; require it to return to the steady-state baseline with nonblank textures and Vulkan validation. **Dependency:** Windows/Vulkan only; inspect Metal’s separate policy.

20. **Kanban metadata ordering searches quadratically.** For every saved filename, `apply_card_metadata()` searches the complete lane vector from its start (`modules/kanban/draxul-kanban/src/kanban_store.cpp:228–252`). A fully listed 10,000-card lane entails about 50 million comparisons on startup and each reload. Visible-row rendering and debounce do not affect this matching. **Change:** use a temporary owning filename-to-index map and append unmatched cards in original order; preserve duplicate and stale-name behavior without keys pointing into moved strings. **Validate:** count lookups at 1,000/5,000/10,000 cards in varied orders; require linear growth and identical ordering on both platforms. **Dependency:** independent of finding 6.

21. **Fragmented Neovim messages repeatedly allocate and decode their prefixes.** After an incomplete packet, `NvimRpc::reader_thread_func()` retries decoding from the same offset on the next read (`libs/draxul-nvim/src/rpc.cpp:467–478`). The codec allocates a string of its advertised length before discovering missing body bytes (`src/mpack_codec.cpp:146–157`). An 8 MiB clipboard line arriving through the 256 KiB read buffer needs at least 32 attempts, causing at least 256 MiB of temporary string initialization; fragmented redraw arrays also rebuild earlier nodes. Size caps bound individual messages, not repeated work. **Change:** check body availability before allocation, then retain incremental parser state for complete O(payload) decoding. **Validate:** feed identical packets in 4/64/256 KiB fragments; require allocation and decoded-node counts proportional to payload, preserving malformed/truncated handling on both transports. **Dependency:** none.

22. **The Session-stream writer parses and serializes outbound JSON twice.** `enqueue()` serializes each complete frame (`libs/draxul-server/src/session_stream_service.cpp:57–60,179–187`); the writer reparses and dumps it to add `frame_serial` (`:508–514`). For terminal-output or snapshot frames of B bytes, each client pays another whole-payload parse, temporary JSON tree, and serialization. Queue and 8 MiB frame bounds prevent blow-up but not the repeated throughput cost; serial assignment at dequeue must remain. **Change:** retain an immutable prepared payload and add the serial-bearing envelope at selection, preserving schema, priority order, and byte accounting. **Validate:** count parsed/dumped bytes and delivery p95 under existing multi-pane load tests; require zero whole-payload writer parses and unchanged serial/priority behavior on POSIX and Windows. **Dependency:** none.

## Benchmark order and safeguards

Start with counters for ligature expansion, Rezonality resize creations, idle watcher bytes, and paused SatView propagations; then run the named interaction workloads before and after each change. Preserve the existing event-driven main-loop wait, dirty atlas-region uploads, two frame slots, stream queue/backpressure bounds, Kanban notification debounce, ScoreView’s windowed Roll strip, and off-thread Session checkpointing.
