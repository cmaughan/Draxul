## Moon Texture

`textures/moon_lroc_8k.jpg` is an 8192x4096 high-quality JPEG conversion of
NASA Scientific Visualization Studio's `lroc_color_poles_8k.tif` from the CGI
Moon Kit:

https://svs.gsfc.nasa.gov/4720/

The map is centered on 0 degrees longitude and was adapted from the Lunar
Reconnaissance Orbiter Camera Hapke-normalized WAC color mosaic assembled from
more than 100,000 Wide Angle Camera images. The source TIFF was converted to
JPEG quality 93 without resizing.

Credit: NASA's Scientific Visualization Studio; Ernie Wright (USRA),
visualizer; Noah Petro (NASA/GSFC), scientist; LROC WAC data from the Lunar
Reconnaissance Orbiter Camera team at Arizona State University.

## Live Cloud Map

At runtime SatView asynchronously downloads the latest 8192x4096 greyscale
cloud map from the Live Cloud Maps project and caches it for three hours. The
bundled cloud texture remains the default; enable `Realistic clouds` in the
SatView panel to select the downloaded map. Either map is rendered on a
separate shell approximately 9.5 km above the normalized Earth surface:

https://clouds.matteason.co.uk/images/8192x4096/clouds.jpg

https://github.com/matteason/live-cloud-maps

The downloaded image is used under CC0 1.0. Its EUMETSAT-derived source data
requires this attribution, which is also displayed in the SatView panel:

Contains modified EUMETSAT data

When the service or network is unavailable, SatView keeps using the bundled
`earth_clouds_8k.jpg` texture.

## Star Catalog

`catalog/stars.dxstar` is a compact binary catalog generated from the Hipparcos
main catalog (`I/239/hip_main`) through VizieR:

https://cdsarc.cds.unistra.fr/viz-bin/cat/I/239

The file contains the 100,000 brightest usable Hipparcos records sorted by
visual magnitude. Each record stores a render-space unit direction, source
visual magnitude, saturated display color, and tiny-quad screen size. SatView
defaults to drawing stars with apparent visual magnitudes from -1.5 through 6.0.
The UI exposes minimum and maximum apparent-magnitude controls; records outside
that range are not uploaded for drawing, and stars inside it are scaled across
the selected range. A separate brightness scalar multiplies the resulting
starfield without changing which stars are included.

## Constellation Lines

`catalog/constellations.dxline` contains 656 deduplicated line segments covering
the 88 Western constellation figures. It is generated by
`scripts/build_satview_constellation_catalog.py` from ConstellationLines v1.3 by
Marc van der Sluys, with its Bright Star Catalogue identifiers cross-matched to
the Hipparcos astrometry used by SatView and J2000 coordinates as a fallback.
These lines are one interpretive Western stick-figure set, not an IAU standard.
Other applications may use different stars or branch topology for the same
named constellation; in particular, this catalog is not expected to match
Stellarium's Modern sky culture exactly. Those differences are source-data
choices rather than projection or rendering errors. The separately bundled
constellation boundaries are the authoritative IAU-defined sky regions.
ConstellationLines is licensed CC BY 4.0; the complete source, DOI, license, and
modification notice are recorded in
`catalog/CONSTELLATION_LINES_ATTRIBUTION.md`. The runtime asset stores only
render-space unit-direction pairs and is loaded without network access.

## Constellation Boundaries And Names

`catalog/constellation_boundaries.dxbnd` contains the complete shared boundary
linework and 89 named area anchors for the 88 IAU constellations. It is generated
by `scripts/build_satview_constellation_boundary_catalog.py` from J2000 GeoJSON
in D3-Celestial pinned to commit
`7e720a3de062059d4c5400a379146a601d9010e0`. Long boundary spans are subdivided
to at most one degree before being stored as render-space unit directions.

D3-Celestial is licensed under BSD 3-Clause. Full source, transformation, and
license details are recorded in
`catalog/CONSTELLATION_BOUNDARIES_ATTRIBUTION.md`. The runtime asset is loaded
without network access.

SatView renders the boundaries as solid red screen-space lines with an
independently configurable width, and renders the ranked area names through
Draxul's active font atlas. Both overlays are optional in Globe and Ground
views and are omitted from the 2D body maps.

## Milky Way Background

`textures/milky_way_nasa_4k.jpg` is a 4096x2048 sRGB conversion of NASA
Scientific Visualization Studio's linear OpenEXR Milky Way background from
Deep Star Maps 2020. It is a plate carree ICRF/J2000 celestial map centered at
0 hours right ascension, with right ascension increasing to the left. The
source deliberately omits bright catalog stars, which prevents duplication
with SatView's Hipparcos star layer. Full source, coordinate, transformation,
and credit details are in `textures/MILKY_WAY_ATTRIBUTION.md`.

Regenerate the texture from the repository root with FFmpeg on `PATH`:

```powershell
python scripts\build_satview_milky_way_texture.py
```

## HDR Rendering

SatView samples the Earth, Moon, Sun, and cloud color maps as sRGB textures and
renders the complete scene in linear light to an `RGBA16F` target. The scene
uses the highest supported common color/depth MSAA mode in the order 4x, 2x,
then 1x, resolves before tone mapping, applies the ACES curve using the saved
`Exposure` and `White point` controls, and lets the final sRGB attachment encode
the display image. `Star brightness` remains a star-only linear-light gain;
exposure affects the whole scene.

Enable `HDR buffer debug` in the SatView panel to open the `SatView HDR
Buffers` window. It reports the active MSAA fallback and displays a sample
difference heat map, the resolved HDR image, and the final tone-mapped image.

Regenerate it from the repository root with:

```powershell
python scripts\build_satview_star_catalog.py --max-stars 100000
```

## Sample Catalog

`catalog/sample_gp.json` is a tiny synthetic fixture using the CelesTrak GP JSON
field names. It is not downloaded satellite data; it exists so SatView can
exercise the catalog parser and status path deterministically while offline.

## Lunar Ephemeris Catalogue

`catalog/lunar_ephemeris.csv` is the generated curated catalog for lunar mission
vectors. Each object needs at least two time-ordered rows with the columns
shown in the file. `FRAME` must be `MOON_ICRF`; positions and
velocities are Moon-relative kilometres and kilometres per second. `SOURCE`
should identify the Horizons, NASA SSC, or SPICE source used to generate the
samples. `TRACK_HORIZON_MINUTES` controls the default displayed path span.
SatView interpolates only inside the supplied UTC Unix-time range and
does not extrapolate stale mission data. An empty header-only file is valid and
leaves matching SATCAT objects in their catalogue-only or summary-estimate
state.

Generate a current curated window from NASA/JPL Horizons and NASA SSC:

```powershell
py scripts\build_satview_lunar_ephemeris.py
```

The target manifest maps LRO, CAPSTONE, Danuri, and Chandrayaan-2 to Horizons,
and ARTEMIS P1/P2 to NASA SSC predictive ephemerides. SSC positions are
converted from geocentric GEI J2000 into Moon-relative ICRF with matching JPL
Moon vectors. Use `--start` and `--stop` for a reproducible ISO-date interval.
The generator writes atomically and clamps known mission coverage bounds rather
than extrapolating them.

`catalog/lunar_dispositions.csv` is a small primary-source-backed overlay for
SATCAT rows known to have landed or impacted despite lacking a decay date. It
currently excludes Chang'e-4 and HAKUTO-R M2 from the orbiting-object list; see
`LUNAR_DISPOSITIONS_ATTRIBUTION.md` for provenance.
